# Дневник сделок

Дневник трейдера для iPhone и Android: сделки вручную или автоматически из MetaTrader 5, PnL, R, статистика, разбор дисциплины. Работает как приложение на главном экране (PWA), сделки шифруются на устройстве.

- `web/` — само приложение (публикуется на GitHub Pages)
- `supabase/schema.sql` — база данных и правила доступа
- `mt5/TradeJournalSync.mq5` — робот для MetaTrader 5 (только чтение)
- `configure.py` — подключить приложение к своему проекту Supabase
- `TradeJournal/` — первая версия для iPhone (Swift), без синхронизации
- `tests/` — проверки безопасности и шифрования

## 1. Настройка (один раз, делает владелец)

### GitHub — отдельный аккаунт только под дневник
Все сайты одного аккаунта GitHub Pages живут на одном адресе `<логин>.github.io` и делят память браузера. Поэтому:
1. Создай **отдельный аккаунт или организацию** GitHub только для дневника — и больше ничего на нём не публикуй.
2. Включи **двухфакторный вход** (Settings → Password and authentication).
3. Создай репозиторий (например, `trade-journal`), загрузи проект.
4. **Settings → Pages → Source: GitHub Actions** — сайт будет собираться из папки `web/`.
5. **Settings → Environments → github-pages → Required reviewers**: добавь себя. Каждая публикация будет ждать твоего подтверждения — случайно или незаметно код не изменится.
6. **Settings → Branches**: правило для `main` — запрет force-push и удаления.

### Supabase — база и вход
1. [supabase.com](https://supabase.com) → **New project** (регион поближе, например Frankfurt). Пароль базы — в менеджер паролей.
2. **SQL Editor → New query** → вставь целиком `supabase/schema.sql` → **Run**.
3. **Authentication → Sign In / Providers**: выключи **Allow new users to sign up** (регистрация только по приглашению), минимальная длина пароля — **10**.
4. **Authentication → URL Configuration → Site URL**: адрес приложения, например `https://<аккаунт>.github.io/trade-journal/`.
5. Подключи приложение: в **Project Settings → API** возьми *Project URL* и **публичный** ключ (*anon* или *publishable*, но **не** *service_role* / *secret*) и выполни:
   ```bash
   python3 configure.py https://xxxx.supabase.co <публичный ключ>
   ```
   Скрипт запишет `web/config.js` и разрешит странице связь только с этим адресом. Секретный ключ он не примет.

### Пригласить человека (себя тоже)
1. SQL Editor:
   ```sql
   insert into public.allowed_emails (email) values ('друг@example.com');
   ```
2. **Authentication → Users → Invite user** → тот же email. Придёт письмо со ссылкой.

Закрыть доступ: **Authentication → Users → … → Ban user** (или удалить), и `delete from public.allowed_emails where email = '...';`.
Встроенная почта Supabase отправляет лишь несколько писем в час; для большого числа приглашений подключи свой SMTP (Authentication → Emails).

## 2. Вход на телефоне

1. Открой ссылку из письма-приглашения: на Samsung — в **Chrome**, на iPhone — в **Safari**. Задай пароль (от 10 символов, буквы и цифры).
2. Приложение создаст **ключ шифрования** (`tjk_…`). **Сохрани его в менеджере паролей.** Без ключа сделки не восстановить — ни тебе, ни владельцу.
3. **Установи на главный экран** (обязательно на iPhone: иначе Safari через 7 дней без посещений стирает данные сайта):
   - Samsung (Chrome): меню ⋮ → «Добавить на главный экран»
   - iPhone (Safari): «Поделиться» → «На экран „Домой“»
4. На втором телефоне: вход по паролю + ввести сохранённый ключ.
5. Забыл пароль — «Забыл пароль» на экране входа. Раз в 30 дней приложение попросит пароль заново.

## 3. Робот MetaTrader 5 (автоматические сделки)

Робот работает в MT5 **на компьютере** (на телефонах Apple и Google роботов не разрешают). Сделки, открытые с телефона, тоже попадут в дневник — робот видит всю историю счёта.

1. В приложении: **Настройки → Подключить MetaTrader** — появятся адрес, публичный ключ, токен и **ключ робота** (`tjr_…`).
2. В MT5: **Файл → Открыть каталог данных** → `MQL5/Experts` → положи `mt5/TradeJournalSync.mq5`, открой его в **MetaEditor** и нажми **Компилировать** (F7). Готовых `.ex5` от других людей не запускай — их нельзя проверить.
3. **Сервис → Настройки → Советники**: *Разрешить WebRequest для следующих URL* → добавь адрес Supabase.
4. Перетащи **TradeJournalSync** на график. *Входные параметры* — 4 значения из шага 1. На вкладке *Общие* **сними** «Разрешить алгоритмическую торговлю»: роботу она не нужна, и так торговля для него запрещена самим терминалом.
5. Во вкладке *Эксперты*: «робот запущен… Только чтение — торговых действий нет», в углу графика — «Синхронизировано…». Если «самопроверка шифрования не пройдена» — робот ничего не отправляет.

Робот отправляет изменения раз в 5 минут (не в момент сделки). Не переносите его на **виртуальный хостинг MQL5**: параметры робота (токен и ключ робота) окажутся на серверах MetaQuotes.
Для полной гарантии можно запускать робота в терминале, подключённом по **инвесторскому паролю** (только просмотр): тогда брокер отклонит любую сделку из этого терминала.
Если токен или ключ робота засветились — **Настройки → Отозвать**, создай новый.

Без робота: MT5 на компьютере → вкладка *История* → правый клик → *Отчёт* → *HTML* → в приложении **Настройки → Загрузить отчёт MT5**.

## 4. ИИ-аналитик (по желанию)

Вкладка **Аналитик**: выбираешь рынок (крипта, золото, форекс, акции США), тикер и горизонт (4 часа – неделя). Сервер берёт свечи 15m/1h/4h/1d (Binance Futures, запасной Bybit; Yahoo для остального), считает EMA, RSI, ATR, уровни, Claude Opus 5.5 ищет свежие новости и даёт три сценария: рост до цели, падение до цели, без цели — с вероятностями. Сервер проверяет ответ (сумма 100%, цели по разные стороны от цены и соразмерны ATR, ссылки только из реального поиска). После горизонта приложение само сверяет прогноз со свечами: что было достигнуто первым, доля сбывшихся, Brier и калибровка.

Включить (делает владелец, один раз):
1. Ключ API на [console.anthropic.com](https://console.anthropic.com) → **API keys**. Поставь там месячный лимит расходов (один анализ ≈ $0,1–0,4).
2. Установи [Supabase CLI](https://supabase.com/docs/guides/cli) и выполни в папке проекта:
   ```bash
   supabase login
   supabase link --project-ref <id проекта>
   supabase secrets set ANTHROPIC_API_KEY=<ключ> APP_ORIGIN=https://<аккаунт>.github.io
   supabase functions deploy analyst
   ```
3. Схема (`supabase/schema.sql`) уже содержит лимит: **10 анализов в сутки** на человека; неудачный анализ лимит не списывает.

Ключ Anthropic хранится только в секретах функции — в приложение и в репозиторий он не попадает.

## Как устроена безопасность

| Угроза | Защита |
|---|---|
| Чужой человек откроет приложение | Аккаунты только по приглашению владельца; открытая регистрация выключена; вход по паролю; раз в 30 дней — повторный вход. |
| Один пользователь попробует прочитать или изменить сделки другого | Row Level Security в базе: каждый запрос видит только строки своего аккаунта. Проверено атаками: `tests/test_db_security.py`. |
| Владелец базы, Supabase или GitHub посмотрят сделки | Сделки шифруются на устройстве (AES-256 + HMAC-SHA256) ключом, который есть только у пользователя. На сервере — только шифр и непрозрачные id: ни тикеров, ни сумм, ни номера счёта, ни заметок. Длина записей выровнена. |
| Кто-то подключится к MetaTrader через дневник | Такой связи нет: дневник не знает пароля MetaTrader. Данные идут только *из* терминала *в* дневник. |
| Робот совершит сделку | В коде робота нет торговых функций; «Алгоритмическая торговля» для него выключена; можно запускать по инвесторскому паролю. |
| Украдены токен или ключ робота | По токену можно только отправлять позиции — читать нельзя, служебные записи недоступны, не больше 30 отправок в минуту. Ключ робота открывает только позиции MT5, но не заметки и ручные сделки. Токен отзывается одной кнопкой. |
| Кто-то забьёт базу мусором | Лимит 10 000 записей и 20 МБ на пользователя. |
| Вредоносный код на странице | Политика безопасности (CSP): только свои скрипты, без встроенного кода, связь только с вашим адресом Supabase; запрет работы внутри чужого фрейма. |
| Подобрали пароль и удалили всё | Если с сервера разом пропадает больше половины записей, приложение не стирает копию на телефоне без подтверждения. Копию можно сохранить в файл (она зашифрована). |

**Честные ограничения — расскажите о них друзьям**
- **Доверие к коду сайта.** Приложение загружается с GitHub Pages. Тот, кто управляет аккаунтом GitHub, может изменить код так, чтобы он отправил ему ключи. Поэтому: отдельный аккаунт, двухфакторный вход, ручное подтверждение каждой публикации (см. настройку). Код открыт — его можно проверить. Кому нужна максимальная независимость — может опубликовать свою копию `web/` на своём GitHub Pages и подключить её к той же базе.
- **Что видно владельцу базы:** email пользователей, сколько у каждого записей и когда они менялись (с точностью до интервала отправки робота). Содержимое — нет.
- Ключ и вход хранятся на телефоне. Защищай телефон кодом блокировки; на чужом устройстве нажимай «Выйти». При потере телефона «Выйти на всех устройствах» с другого закроет вход к серверу, но **не сотрёт** копию сделок и ключ на самом потерянном телефоне — от этого защищает только код блокировки.
- Отзыв токена робота не меняет **ключ робота** (`tjr_`): он выводится из основного ключа. Если засветился сам ключ робота — новые позиции MT5 можно прочитать только вместе с утёкшим шифром с сервера; полностью сменить его можно лишь новым основным ключом.
- Лимит 10 000 записей на пользователя: скальперам с сотнями сделок в день стоит уменьшить `InpDays` у робота и периодически чистить старые позиции.
- Потерянный ключ = потерянные сделки. Это цена того, что их не может прочитать никто другой.
- **ИИ-аналитик:** для анализа на сервер и в Anthropic уходит тикер и рыночные данные (не сделки, не заметки, не ключ). Функция их не сохраняет; сами прогнозы хранятся зашифрованными, как сделки. Владелец видит в базе только счётчик анализов за день. Прогноз — не инвестиционный совет.
- Робот должен быть запущен в MT5 на компьютере, иначе новые сделки появятся после следующего запуска.
